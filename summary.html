4. namespace 采集与非 root fallback

四、proof 安全边界

由于曾出现 CAP_SYS_TIME proof 直接改动宿主机时钟的事故，后续所有利用脚本都收敛到了统一的安全门：

  1. 先做静态分析，判断动作是否会触碰宿主全局状态。
  2. 再做一次性容器预跑，确认不会外溢到宿主全局面。
  3. 正式运行前检查目标子系统是否与宿主隔离；未隔离则停止，或先补成受控宿主资产。

允许的 proof 只剩两类：

  • 容器内闭环动作，例如 raw socket、mknod、file capability、BPF_PROG_TEST_RUN、ioperm。
  • 受控宿主资产动作，例如临时文件、临时目录、临时进程、临时 mount subtree。

五、当前遗留项

项 状态 原因
CAP_SYS_TIME 未做 proof 最短路径直接碰宿主全局时钟，违反宿主外溢预检。
CAP_AUDIT_CONTROL 未做 proof Linux audit 在当前环境属于宿主全局面，不适合直接验证。
CAP_MAC_OVERRIDE / CAP_MAC_ADMIN 未做 proof 当前主机是 SELinux，不是 Smack，缺少有效实验面。
CAP_CHECKPOINT_RESTORE 未做 proof 现有内核/运行时下没有找到干净的容器内闭环 proof。
CAP_DAC_OVERRIDE + writable host mount 检测成立，probe 被拦 受控写入动作被宿主 SELinux / labeling / 其他 LSM 挡住，但危险组合本身已成立。
